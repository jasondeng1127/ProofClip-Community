# Community release pipeline

Deterministic Commercial → Community export for ProofClip Community.

## Layout

- `edition-boundary.json` — A0 machine-readable edition boundary (the single source of truth).
- `overlay/` — A1 community-owned files. Every path here replaces or adds the same
  relative path in the generated tree. Upstream export never overwrites overlay files.
- `export-community.mjs` — A2 thin pipeline: copy upstream → exclude → overlay → transform → provenance.
- `verify-generated-tree.mjs` — A5 commercial-boundary scanner for the generated tree.
- `tests/` — pipeline self-tests (determinism, exclusion, overlay, provenance, scanner).
- `out/` (gitignored) — generated Community 0.8 tree + `PROVENANCE.json`.

## Provenance semantics

`PROVENANCE.json` (generated by `export-community.mjs`) describes the SOURCE
tree only. It supersedes the legacy `COPYING_MANIFEST.json` (which is not part
of the Community 0.8 boundary). Build artifacts are listed under
`buildArtifacts` with an explicit note and are never part of the `files` list:
`worker/dist/worker.mjs` is built at release cut time from the artifact source
and is bound to it via the release record's `artifact.bundleSha256` and the
audit's bundle-reproducibility check.

## Release governance (B3)

```powershell
node release/cut-release.mjs                        # cut the ZIP artifact + release record
node release/release-audit.mjs                      # automatic gates (record/artifact/source/commit/dirty/bundle/zip)
node release/release-audit.mjs --include-tests      # also run both offline suites (guard excluded; needs pwsh+git env)
node release/release-audit.mjs --release-ready      # strict mode: full rehearsal evidence + policy tag + verified git (exit 1 when missing)
node release/set-rehearsal.mjs --name freshDeploy --result PASS --executor <who> --environment <what> --evidence <path|summary>
```

Tag policy for release-ready: `v<version>` (final) or `v<version>-rcN` (release
candidate) at HEAD. Fingerprint identity is never sufficient for release-ready;
git commit verification is mandatory.

Mainline governance gates (see docs/release-process-governance.md):
- DEFAULT_BRANCH_RELEASE_ALIGNMENT: default branch == main, current branch ==
  main, release commit is an ancestor of origin/main, origin/main carries the
  release version + migrations + tooling + CI (checked on every audit).
- RELEASE_TAG_MUST_DESCEND_FROM_MAIN: the policy tag's commit must be an
  ancestor of origin/main (release-ready).
- DEFAULT_CLONE_SMOKE_TEST: `release/verify-cloned-tree.mjs --remote <url>
  --version <v> --record` performs a fresh `git clone` (no ref flags) and
  verifies main == target version + discriminators + required files; the
  recorded result is required by release-ready.
- README_ASSETS: README relative references must resolve (release-ready).
- Worktree governance: `git worktree list` is classified
  (ACTIVE_REQUIRED / TEMPORARY / UNKNOWN); TEMPORARY/UNKNOWN worktrees block
  release-ready.
- EDITION_DIFF_REPORT: cut records what came from Commercial, what was
  excluded, and the leak-scan result (UNEXPECTED_COMMERCIAL_FEATURE_DIFFUSION
  must be NONE).

Truth model (frozen):
- `release/provenance/community-<version>.json` is the ONLY audit input for
  provenance (tracked in Git — it is part of the source distribution spec).
- `release/out/` is an intermediate export staging tree (gitignored, always
  reproducible).
- `release/records/` (current + history) and `release/artifacts/` (ZIP +
  sha256) are release evidence produced by a cut — NOT tracked, bound to the
  frozen HEAD + ZIP sha, and intended for GitHub Release assets / CI release
  evidence. This avoids the record-modifies-HEAD loop.

The ZIP packaging boundary is separate from the source boundary. The
`packageExclusions` list in `edition-boundary.json` removes private migration
records, acceptance/backlog/planning material, runtime probes, local Wrangler
state, and generated Worker output. The release cutter copies the Worker
bundle explicitly after applying those exclusions, so a local `worker/dist/`
or `.wrangler/` directory cannot silently enter a candidate.

Release order:
```text
Source + canonical provenance
        -> commit frozen HEAD
        -> cut artifact (record binds HEAD + ZIP sha + packaging manifest)
        -> real rehearsals bind same HEAD/ZIP (set-rehearsal enforces it)
        -> tag HEAD (v0.8.0-rcN / v0.8.0)
        -> release-audit --release-ready
```

- `release/records/release-record.json` is the CURRENT release record
  (`state: STAGED` until rehearsals pass and the final audit is green).
- History snapshots are kept as `release/records/release-record-<version>-<stamp>.json`.
- Stale detection: the audit recomputes the workspace fingerprint and fails if
  the source moved after the cut.
- Source commit binding is captured when git is available; otherwise
  `commit: null` and the audit reports it before release review.
- Rehearsals (fresh deploy, 0.7->0.8 upgrade) are recorded in the release
  record's `rehearsals` field and are required before
  `READY_FOR_RELEASE_REVIEW`.

## Usage


```powershell
node release/export-community.mjs            # reads edition-boundary.json, writes release/out/community-0.8.0
node release/verify-generated-tree.mjs       # scans the generated tree; exit 0 = clean
node --test release/tests/export-pipeline.test.mjs
```

## Provenance

`PROVENANCE.json` records, per output file: source (`upstream` | `overlay`),
SHA-256, and transform application. It is deterministic (no timestamps) so two
runs with the same inputs produce byte-identical trees.

## Boundary rules (A1)

Product core follows upstream; self-host/distribution layer belongs to Community.
Upstream-excluded material (commercial facilities, private deployment state)
never enters the tree. Community-owned top-level material is maintained in the
repository, while only the public subset allowed by `packageExclusions` enters
the distributable ZIP.

## Schema note (0.7 → 0.8 upgrade)

Community keeps `connections.workspace_id/workspace_name` columns (NULL after
migration) so `migrations/20260813_privacy_nonretention.sql` is a safe cleanup
on both fresh and upgraded databases. OAuth state rows are deleted on use and
pruned by the migration; the community schema has no `consumed_at` column.
